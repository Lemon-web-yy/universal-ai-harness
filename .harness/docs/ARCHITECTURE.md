## 1. 系统形态（多模块集成）

```
┌─────────────────────────── 模块 A（示例：核心服务）───────────────────────────┐
│  组装层（Assembly） → 业务层（Business） → 基础设施层（Infrastructure）        │
│        │                              │                                      │
│        └──── 消息通道 / 接口 ──────────┤                                      │
└──────────────────────────────────────┼──────────────────────────────────────┘
                                       │ 跨模块通信介质（契约档案定义）
┌─────────────────────────── 模块 B（示例：下游消费者）─────────────────────────┐
│  组装层 → 业务层 → 适配层（Adapter） → 基础设施层                              │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
┌─────────────────────────── 模块 C（示例：表现层）─────────────────────────────┐
│  编排（Orchestration） → 核心/通道/组件 → 基础设施                            │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 2. 同构四层模型（所有模块共享的分层语言）

| 层 | 定位 | 通用描述 |
|----|------|----------|
| 层4 组装/应用 | 只做胶水不做逻辑 | 入口编排 + 多源聚合 + 依赖装配 |
| 层3 业务模块 | 状态与业务逻辑 | 业务模块（状态-副作用分离） |
| 层2 协议/通信 | 编解码与分发 | 消息编解码 + 调度器 + 通道封装 |
| 层1 基础设施 | 纯底层封装零业务 | 驱动抽象 / OS 封装 / 外部依赖适配 |

**铁律：依赖严格单向向下（层4→层3→层2→层1），禁止逆向引用与跨层跳跃。**
（记号说明：分层用"层N"文字，避免与 L0-L3 协作评级撞号。）

## 5. 跨切面机制（通用设计模式）

- **回调注册解耦** — 协议层不认识业务，业务通过 `xxx_set_callback(cb, user_data)` 订阅
- **配置表驱动** — 数据描述通道/硬件，代码通用化
- **心跳式调度** — 周期函数；事件消息 + 心跳消息 + pending 补发上报范式
- **多路生产者-单消费者调度** — 多来源共享一条通道
- **自愈 I/O** — 懒初始化 + 断线自动重连；资源热插拔重扫
- **算法纯化** — 算法模块无副作用无全局变量，可独立复用与测试
