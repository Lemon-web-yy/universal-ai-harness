# 经验库 — 通用教训（无编号原则）

> **定位：** 从带编号原始教训（`contracts/workflows/cross-module-change.md` 经验教训区 L01+）提炼的**不带编号通用原则**，按主题分组。与带编号版形成两级结构：编号版供契约引用溯源，本文件供日常速查。
> **维护：** 当某条编号教训被 ≥2 个项目/模块验证为通用原则时，提炼到此处并标注"提炼自 L0X"。

## 契约设计

- 接口契约要写到"抓包可对账"的粒度：消息逐字段表 + 位域全组合速查 + 抓包示例 + 容量预算。（提炼自 L08）
- "不做的事"与"镜像参考模板"是契约的两道闸门：前者防自由发挥，后者防模式发散。（提炼自 L20/L21）
- 契约中明示依赖前置条件（"依赖 X 模块已就绪"），Builder 动手前即可发现依赖缺失。（提炼自 L04）

## 跨线程 / 跨进程 / 网络

- 流式数据必须累积缓冲 + 按分隔符拆包，一次 read/recv 可能是半包、也可能是多包混合。（提炼自 L10）
- 线程间数据交接必须显式声明连接语义（工作线程解析 / 主线程消费），数据所有权随信号转移。（提炼自 L09）
- 阻塞读循环必须保留中断响应路径（超时检查退出标志），否则线程无法优雅退出。（提炼自 L09）

## 架构与代码

- 数据归属：谁生产数据谁负责语义翻译；通道模块不认识业务，UI 组件不认识通道。（提炼自 L14）
- 组装层调用模块应"一行搞定"，暴露内部多步骤即封装不足。（提炼自 L15）
- 尺寸/阈值/路径全部命名常量，裸魔法数字是审核硬伤。（提炼自 L17）
- 同类模块接口结构镜像同构（枚举+API+常量），结构差异必须在 ADR 说明理由。（提炼自 L23）
- 状态-副作用分离：API 只写状态，周期函数是唯一副作用出口——这让业务逻辑天然可单元测试。

## 协作流程

- 子 agent prompt 给档案路径不给全文，单一真相源不粘贴。（提炼自 L05）
- 子 agent 按需列，不默认列全——每多拉一个模块就多一份风险面。（提炼自 L07）
- 单端先行合法：契约按通信边界分段覆盖，先打通一端。（提炼自 L19）
- 收尾必跑索引自检，索引漂移让后续导航扑空。（提炼自 L22）
