#### 1.2 消息结构

```
字段偏移:  0    1    2    3   ...
内容:     HEADER  VER  LEN  OPCODE  [PAYLOAD...] [CHECK]
```

| 字段 | 偏移 | 长度 | 值 | 说明 |
|------|------|------|-----|------|
| 消息头 | 0 | 2B | `0xAA 0x55`（示例） | 固定 |
| 数据长度 | 2 | 1B | | OPCODE + PAYLOAD 字节数 |
| 操作码 | 3 | 1B | | |
| 校验和 | | 1B | | `(LEN + OPCODE + PAYLOAD...) & 0xFF` |

**命名常量定义**（禁止裸魔法数字，教训 L17）：

```c
#define XXX_OPCODE           0xNNU
#define XXX_MSG_SIZE         NU
/* 状态位域掩码等 */
```

#### 1.3 状态/字段位域定义（如有）

| Bit | 掩码 | 名称 | 含义 | 数据源 |
|-----|------|------|------|--------|

**位域全组合速查**（2^有效位数 种，防映射语义错误）：

| 状态 | 二进制 | 含义 | 常见度 |
|--------|--------|------|--------|

#### 1.4 上报/推送节奏（事件消息 vs 心跳消息）

| 类型 | 频率 | 触发条件 | 丢消息策略 |
|------|------|----------|----------|
| 事件消息 | 状态变化时立即 | <条件> | pending 补发，不丢 |
| 心跳消息 | N Hz | 周期 | 失败直接丢，下个心跳补 |

```c
/* pending 机制骨架（先 Send 成功才清 pending） */
static uint8_t s_event_pending = 0;
/* 事件检测 → 入队失败记 pending → 心跳窗口优先补发 */
```

#### 1.5 接收端解析约束（硬性要求，不是设计建议）

1. **操作码分发**：独立解析分支，不与其他操作码混合
2. **载荷长度动态判断**：按 LEN 字段，不能硬编码长度
3. **校验验证**：失败丢弃
4. **保留位掩码过滤**：应用 `status & FIELD_MASK` 提取有效位
5. **边界保护**：外部输入不可信任，异常值丢弃或钳位
